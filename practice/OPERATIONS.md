# Dashboard runtime and verification

Run with Node.js 24 or newer and pnpm. `pnpm dev` starts the local dashboard; `pnpm build` checks the production bundle; `pnpm test` checks indexed history and durable tasks using temporary synthetic data.

`PRACTICE_AGENT_DIR` may point to an absolute, persistent agent data directory. The default is `../agent`. The dashboard requires a Node server with filesystem access; it is not a static site or a Cloudflare Workers application.

The dashboard incrementally indexes the existing activity log and call metadata into `practice.sqlite` in that directory. Task assignments, notes, priorities, deadlines and edit history live in SQLite and must be backed up. Use a SQLite-aware backup or stop the app before copying the database with its WAL files. Do not treat this database as a disposable cache. Keep runtime patient data and secrets out of deployment artifacts.

Pagination and summaries use indexes instead of loading every historical transcript. Cold imports still scan existing history; warm call synchronization still enumerates directories. This is a single-server improvement, not evidence of multi-server or high-concurrency capacity. Built-in SQLite currently emits an experimental warning. Next's dynamic filesystem tracing warning also remains and deployment packaging needs review.

The automated fixture covers 10,000 events and 260 calls, bounded pagination, practice-scoped queries, task persistence after reopening, stale-edit conflicts, partial log appends and rewritten logs. These are correctness checks, not a production load test.

Authentication and role-based practice access are implemented; see AUTH_SETUP.md to activate Google/Apple and provision the owner. Calendar failures now create follow-up tasks, and local recording/transcript persistence is disabled for new calls. The voice agent must be restarted to load these changes. Before real clinic use, complete live provider testing, reliable PMS scheduling, recording consent, retention and country-specific data protection review. Campaign sending remains unimplemented. Legacy booking conversion remains unknown.

Demo task edits are temporary and reset when leaving the page. Real task edits persist. CSV appointment exports include all matching indexed records, rather than only the visible page.

## System work: login, voice and campaigns

- Login remains Auth.js invitation-only email authentication. Signed sessions last eight hours; email links last fifteen minutes and are single-use. Throttled requests now return an explicit retry state rather than a false sent state. Do not change token generation to a six-digit number: short codes need a separate challenge model with attempt limits and binding. A future passkey/SSO integration should use a maintained provider and migration plan rather than a second ad hoc session system.
- Pipecat owns the realtime media path. n8n is not inserted between speech recognition, LLM and synthesis. Document search is moved off the event loop, bounded to six seconds, with an SDK timeout and no retries. Callback/escalation tools report persistence failures and do not invent response times. Escalation is a saved priority task, not a telephone transfer. Locale/date context uses the clinic timezone. Non-English clinics reject the English-only PhoneLLM configuration and require a deliberate non-English Deepgram voice choice.
- Run agent/.venv/Scripts/python.exe agent/preflight.py for a credential-presence/configuration report; it does not validate live audio or telephone ingress. Readiness checks are not a certification. In production verify telephony webhook signatures and trusted number routing, test interruptions/silence/disconnects, and connect a real staffed handoff destination before advertising live transfers. Do not enable audio/transcript retention without the agreed retention/consent setup.
- Campaigns now support appointment-reminder drafts, audience validation, explicit simulation approval, pausing, contact withdrawal and a durable duplicate guard across campaigns. Due reminders simulate only on weekdays 09:00–18:00 in the selected timezone; missed/expired appointments are excluded. This policy is an implementation default, not a legal determination. Recipients require an explicit confirmed-appointment/contact check. These records are separate from appointment requests and never confirm a booking.
- No campaign SMS, email or outbound telephone call is implemented or enabled in this slice. Live sending needs a clinic-approved channel/template, supported opt-out and reply callbacks, provider delivery status, source-agenda freshness, and a separate approved dispatch step. Provider acceptance must not be labeled delivery. A timeout after an uncertain send must go to reconciliation rather than blind retry. Recalls and missed-call follow-ups can reuse the orchestration pattern but need their own eligibility rules.
- Keep campaigns.sqlite and email-auth.sqlite on private persistent storage. All app workers on this host must share the database. Moving to multiple hosts requires a shared transactional store and distributed rate limiting.
